# AI-Powered Keyword Clustering Engine

Groups SEO keywords into topic clusters with (1) a fixed lexical baseline (word TF-IDF + agglomerative
clustering) and (2) a semantic method (`all-MiniLM-L6-v2` embeddings + HDBSCAN). Outputs are for **human
review** - clusters are *not* ranking factors and nothing here predicts Google rankings.

> **CRITICAL DATA STATUS: ALL ACTIVE INPUTS ARE SYNTHETIC**  
> All bundled keyword datasets (`data/synthetic/sample_keywords.csv`, `data/synthetic/smoke_keywords.csv`,
> `data/synthetic/ai_search_keywords.csv`) are **SYNTHETIC** test fixtures generated by scripts in `scripts/`.
> They validate pipeline execution, software engineering correctness, and algorithm mechanics only, NOT real-world SEO performance.

* **Evaluation Finding:** **EVALUATED AND REJECTED as a keyword clustering corpus.**
  * The dataset is an aggregate monthly search volume index for 14 AI brands across 20 countries.
  * It contains **zero natural language query phrases or long-tail keywords**.
  * Clustering 14 single-brand names violates the requirements of unsupervised topic clustering.

## Setup (fresh environment)
```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest -q                  # 12 tests, offline, no model download needed
```
Record in your run log: Python version, OS (also saved automatically in `data/output/run_metadata.json`).

## Input schema
UTF-8 CSV with a column named `keyword` (extra columns ignored). Blank/invalid rows are reported and excluded.

## Run
```bash
python scripts/generate_synthetic.py                                     # (re)create synthetic benchmark data
python run_pipeline.py tune --input data/synthetic/sample_keywords.csv   # 1. parameter search on dev subset
#   -> reports/tuning_results.csv + reports/tuning_preview.txt ; inspect, then FREEZE values in config.py
python run_pipeline.py run  --input data/synthetic/sample_keywords.csv   # 2. final run (both methods)
#   -> data/output/*.csv, reports/human_review_sheet.csv
#   3. fill rating_1_to_5 etc. in reports/human_review_sheet.csv, then run step 2 again:
#      evaluation_summary.csv now contains mean_human_coherence and pct_clusters_rating_4_or_5.
python run_pipeline.py run --input data/synthetic/smoke_keywords.csv --methods baseline   # quick smoke test
```
The first semantic run downloads the model (~90 MB) and needs internet once; afterwards it runs offline on CPU.

## Outputs (`data/output/`)
| File | Content |
|---|---|
| `keyword_assignments.csv` | one row per valid input record **per method** (`method` column), incl. duplicates; noise = `cluster_id -1`, `is_noise true` |
| `cluster_summary.csv` | one row per non-noise cluster: size (unique keywords), representative (closest to centroid), members (`;`-separated) |
| `data_quality_report.csv` | input / blank / invalid / duplicate / unique counts, length stats |
| `evaluation_summary.csv` | n_clusters, noise_rate, silhouette, human metrics, runtime, peak memory |
| `run_metadata.json` | dataset name + SHA-256, timestamp, config, model revision, package versions |

`reports/cluster_diagnostics.csv` has size distribution, singleton share and largest-cluster share.

## Design decisions / documented choices
* Clustering is fitted on **unique normalized keywords**; assignments are mapped back to all rows (A5).
* Blank/invalid rows are excluded from assignments but counted in `data_quality_report.csv` (not silent).
* `similarity_to_representative` = cosine similarity to the representative, clipped to [0,1]. It is **not a probability**.
* Baseline: sklearn `AgglomerativeClustering(n_clusters=None, distance_threshold=t, metric="precomputed", linkage="average")`
  on a cosine-distance matrix (dense n x n; ~200 MB at 5,000 keywords). Deviation from the stock TF-IDF
  settings: `token_pattern=r"(?u)\b\w+\b"` keeps 1-character tokens.
* Semantic: embeddings are L2-normalised; HDBSCAN (scikit-learn >= 1.3) uses euclidean distance, which is
  monotonic with cosine on normalised vectors. Fallback: `SEMANTIC_ALGORITHM = "agglomerative"` in `config.py`.
* Baseline has no noise concept (every keyword gets a cluster, many are singletons); HDBSCAN can leave noise.
* Silhouette: cosine metric, noise excluded, `NA` when <2 clusters. It is a weak guide (e.g. it rises when the
  baseline threshold gets looser) - never choose a method on it alone.
* Peak memory = process-wide peak so far (cumulative), not per-method.
* Nondeterminism: HDBSCAN/agglomerative are deterministic; embeddings may differ slightly across hardware/torch versions.

## Known limitations
Synthetic data only unless replaced; similar embeddings do not prove identical search intent; ambiguous
terms ("apple", "python") cluster unpredictably; 1 reviewer unless an SEO practitioner is available.
`src/intent.py` (optional heuristic intent labels) is EXPERIMENTAL and unvalidated.
